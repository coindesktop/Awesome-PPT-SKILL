# 운영 가능한 제안서

프로그램·사업·교육을 실제로 실행할 기획안에 적용한다. 먼저 운영안을 만들고 그 내용을 장표로 표현한다.
목표 숫자나 예산을 임의로 확정해 현실감을 연출하지 않는다.

## 사실과 제안을 구분한다

- **확인된 사실:** 사용자 자료, 공식 자료, 관측한 가격. 출처·기준일을 남긴다.
- **계획 가정:** 대상·정원·일정·단가·목표. `계획안`, `예산 가정`, `견적 확인 필요`처럼 표시한다.
- **미정 사항:** 실제 결정권자·기관·장소·계약. 임의의 기관 로고나 담당자 실명을 넣지 않는다.

특정 기관이 없고 기본 가정으로 진행하도록 위임받았으면 그 범위에서 구체화한다.
기관 이름이 없다는 이유로 실행 과정을 추상적인 문장으로만 채우지 않는다.

## 원본에서 서로 맞출 항목

| 항목 | 확인할 관계 |
|---|---|
| 대상과 정원 | 누구를 어떤 조건으로 모집하며, 공간·지도 가능 인원과 맞는가 |
| 시간과 일정 | 모집 → 준비 → 실행 → 후속 확인 → 종료가 실제 달력·소요 시간과 맞는가 |
| 물량 | 참여자용 + 시연용 + 예비분이 발주 수량과 맞는가 |
| 예산 | 수량 × 단가, 배송·인쇄·강사비·예비비가 총액과 맞는가 |
| 담당과 투입 | 누가 어떤 작업을 맡으며 준비·진행·후속 시간을 합산했는가 |
| 예외 | 모집 미달·결석·준비 지연 등 실제로 가능성이 큰 상황의 조치가 있는가 |
| 완료와 판단 | 무엇을 언제 확인해 계속·보류·수정할지 정했는가 |

모든 항목을 반드시 별도 장표로 만들지는 않는다. 핵심 결정에 필요한 수준으로 본문과 부록을 나눈다.
안전·법률 등 전문 판단이 필요한 내용은 해당 출처를 확인하고, 확인하지 않은 규칙을 꾸며 넣지 않는다.

수량과 금액은 CSV/XLSX 또는 구조화한 기준 자료에서 계산한다. 합계·그룹 집계에는 `pptkit data/pivot`을 사용한다.
예산 목표는 확보된 예산이나 실제 지출과 구분한다. 관측 가격은 견적·재고·향후 가격 보장이 아니다.

## 이용 경험으로 연결한다

신청 → 확인 → 수령 → 사용 → 기록 → 종료 중 필요한 과정을 따라가며,
각 순간에 필요한 안내·물품·양식을 찾는다. 이 중 하나가 [대표 사용물](working-artifacts.md)이 될 수 있다.
대상이 실제로 읽거나 적을 문구까지 설계하면 진행 방식이 더 분명해진다.

형식을 바꿔 비교할 때는 같은 기준 자료를 계속 사용한다. 새로운 디자인마다 예산·인원·일정을 다시 만들지 않는다.
납품 전 제목·표·차트·노트의 수치를 대조하고, 미정인 값이 확정형 문장으로 바뀌지 않았는지 확인한다.
