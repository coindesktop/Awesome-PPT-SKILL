# 사용자가 받거나 쓰는 것을 대표 비주얼로

서비스·교육·참여 프로그램·제품 제안에 사용한다. 대표 비주얼을 꾸미기 전에 실제 이용 장면을 정한다.
성과 보고처럼 데이터 자체가 근거인 자료에는 차트나 비교표가 더 직접적일 수 있다.

## 선택 순서

1. **행동:** 누가 어느 순간에 무엇을 하는가? 예: 처음 참여한 사람이 안내지를 보고 준비한다.
2. **사용물:** 그 행동에 필요한 물건·문서·화면은 무엇인가? 실제 원본을 우선한다.
3. **설명:** 그것을 크게 보여주면 어떤 문장을 덜 써도 되는가? 구성·사용법·차이를 보여주지 못하면 생략한다.
4. **상태:** 실제 자료, 제안하는 양식, 작성 예시 중 무엇인가? 관객이 구분할 수 있게 표시한다.
5. **제작:** 글자·기본 면·표는 native 요소로, 실물 질감·사진·실제 화면은 이미지로 분리한다.

| 주제 | 우선 찾을 대상 | 크게 보여줄 내용 |
|---|---|---|
| 교육·워크숍 | 실습지, 검토지, 완성 산출물 | 작성 전후, 실제 입력 항목, 검토 기준 |
| 공공·커뮤니티 프로그램 | 안내지, 관찰지, 배부 물품 | 받는 것과 사용하는 순서 |
| 업무 서비스 | 실제 화면, 요청서, 결과 보고서 | 한 번의 작업이 끝나는 모습 |
| 실물 제품 | 실제 제품·구성품·포장 | 크기 관계, 조작부, 사용 장면 |
| 운영 제안 | 작업표, 일정표, 실행 조건표 | 담당·자원·완료 기준의 연결 |
| 조사·성과 보고 | 원자료, 비교 차트, 현장 기록 | 주장과 직접 연결되는 근거 |

앱이 없는 프로그램에 휴대전화 화면을 만들어 넣지 않는다. 아직 없는 문서라도 **실제로 쓸 수 있는 제안 양식**은
설계할 수 있다. `제안 양식`, `작성 예시`를 표시하고 실제 운영·성과 증거처럼 제시하지 않는다.

## 편집형 사용물 만드는 법

`pptkit html init`으로 생성되는 `deck.assets/components/working-artifacts.html`에 3장 예제가 있다.

- **안내지 + 기록지:** 대표 사용물 하나를 크게, 보조 사용물은 크기나 위치로 역할을 구분한다.
  종이 면·구분선·번호·라벨을 개별 `data-pptx` 요소로 만든다. 작성 칸에 장식용 가짜 수치를 채우지 않는다.
- **교육 검토지:** 원문, 판단할 항목, 수정 결과가 읽히게 설계한다. 문서 전체를 작게 축소하기보다 핵심 부분을 확대한다.
- **실행 조건표:** 조건·확인 자료·미충족 시 조치를 같은 기준으로 비교한다. 표를 이미지로 굳히지 않는다.

사용물 내부에도 위계가 필요하다. 이름 → 사용 순서 → 기록 항목 순으로 읽히게 하고,
주장의 핵심과 무관한 작은 장식·가짜 바코드·상태 표시·로고는 넣지 않는다.
대상을 비스듬히 돌리거나 그림자로 띄우지 않아도 면의 크기, 선, 색, 여백으로 충분히 구분할 수 있다.
현 변환기는 CSS transform·그림자를 지원하지 않는다. 지원 범위에서 정면 구도로 만든다.

예제의 네이비·라임은 제품형 응용 팔레트다. 복사할 때 내용·색·서체를 현재 덱의 토큰에 맞춘다.
일반 장표에 넣을 때는 해당 `section`과 필요한 스타일을 함께 가져오고 상대 경로를 확인한다.

## 덱으로 확장하는 순서

대표 사용물 → 구성과 사용법 → 참여 과정 → 자원과 예외 → 다음 행동은 서비스 제안에서 유용한 순서다.
모든 항목을 한 장씩 만들거나 고정된 장수를 채울 필요는 없다. 독자가 결정하는 데 필요한 항목을 고른다.
사진·큰 숫자·문장·양식·표가 각각 다른 역할을 맡도록 구성한다.

## 검수

- 대표 비주얼만 보고 누가 무엇을 하게 되는지 알 수 있는가?
- 사진이 실제 결과로 오해되거나 예시 양식이 이미 배포된 자료처럼 보이지 않는가?
- 항목·단위·행동 순서가 읽히며 다른 장표의 수량·기간과 맞는가?
- PPT에서 안내 문구 한 곳, 작성 항목 한 곳을 실제로 수정할 수 있는가?
- 표지 외에도 내용에 맞는 구도 변화가 있는가?

씨앗도서관의 같은 운영안을 세 방향으로 바꾼 대화에서 제품형의 안내지·관찰지 표현이 호평을 받았다.
이를 설계 원리로 반영했지만, 별도 사용자·다른 주제에서도 동일한 품질이 나온다는 검증은 따로 해야 한다.
