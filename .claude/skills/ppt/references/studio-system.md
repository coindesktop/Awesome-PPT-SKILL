# Studio 디자인 시스템 사용

새 자료에는 Studio의 토큰·컴포넌트·대표 구도를 적용한다. 설명만 읽고 임의의 카드 레이아웃으로 돌아가지 않는다.

## 방향 선택

주제 이름보다 **독자가 자료를 보고 할 일**로 선택한다.

| 방향 | 독자가 할 일 | 중심 장면 | 전개 방식 |
|---|---|---|---|
| editorial | 관점을 이해하고 관심을 갖는다 | 사진·큰 문장·한 가지 사례 | 장면 → 의미 → 경험 → 핵심 문장 |
| product | 사용하거나 참여하는 모습을 그린다 | 실물·화면·안내지·기록지 | 받는 것 → 쓰는 법 → 변화 → 다음 행동 |
| strategy | 조건을 비교해 승인하거나 판단한다 | 지표·표·차트·운영 조건 | 결론 → 근거 → 자원과 일정 → 결정 |

같은 공공 프로그램도 내부 승인용이면 strategy, 문화 소개라면 editorial,
이용 경험을 보여주는 제안이면 product가 맞을 수 있다. product가 반드시 앱을 뜻하지는 않는다.

사용자가 고른 방향이 우선이다. 요청에서 추론할 수 있으면 선택을 짧게 알리고 진행한다.
세 방향을 요청하면 각각 보여준다. 하나의 덱을 단순히 색만 바꿔 세 개라고 하지 않는다.

```bash
pptkit html designs
pptkit html init deck.html --design editorial
pptkit html preview deck.html
```

`deck.assets/`에 토큰·CSS·서체·에셋·차트 미리보기 도구·`layouts.json`이 함께 복사된다.
처음에는 대표 장표의 이미지를 열어 구도와 글자 비율을 파악한다. 그다음 사용자 자료로 내용과 에셋을 바꾼다.
가상 수치·서비스 이름·사진을 사용자의 사실로 남기지 않는다.
`components/working-artifacts.html`도 함께 복사된다. 안내지·기록지 묶음, 교육 검토지,
실행 조건표를 HTML과 PPT로 미리 볼 수 있다. 외부 이미지 없이 텍스트·도형·표로 구성된 독립 예제다.
`showcase/seed-strategy.png`, `seed-editorial.png`, `seed-product.png`에는 같은 운영안을 세 양식으로 만든
실제 PPT 발췌가 있다. 선택한 방향의 이미지를 열어 글자 비율·여백·리듬을 참고한다.
이는 시각 참고용 이미지다. 완성 장표로 삽입하지 말고 현재 내용으로 편집형 요소를 작성한다.
`showcase/manifest.json`에 사례의 가정·출처·확인 범위가 있다.

## 변경하는 순서

1. 목적과 주장에 맞는 구도를 `layouts.json`에서 고른다. 견본은 완성도 기준이며 장수나 순서의 강제가 아니다.
2. `tokens.css`의 의미 토큰으로 브랜드색과 정보 밀도를 조정한다. 컴포넌트별 임의 색·크기를 남발하지 않는다.
3. 제목·지표·근거의 위계를 유지하며 문구를 넣는다. 넘치면 문장을 줄이거나 장을 나눈다.
4. 사진·제품 화면을 실제 주제에 맞게 교체한다. 본문·라벨은 이미지 바깥의 편집형 텍스트다.
5. 차트는 같은 JSON을 HTML과 PPT가 읽도록 한다. JSON의 수치는 `pptkit pivot` 결과와 연결한다.
6. HTML과 PPT를 모두 렌더하고 비교한다.

## 지켜야 할 핵심

캔버스는 1280×720, 기본 여백은 64px, 12열 그리드다. 일반 본문 23~26px, 제목 48~54px,
표지 70~92px가 시작값이다. Pretendard Regular/Bold와 허용된 자간을 사용한다.
브라우저에서는 번들 서체를 사용하지만 PPT PC에는 설치가 필요하다. 자동 임베딩을 주장하지 않는다.

사진은 `object-fit:cover`로 자연스럽게 크롭하고 native PPT crop으로 옮긴다.
표와 차트는 네이티브 객체이며, 실제 데이터 편집이 가능한지 확인한다.
같은 세 칸 카드·매 장 같은 제목선·무의미한 아이콘을 기본값으로 만들지 않는다.

편집형의 여백, 제품형의 비주얼 비중, 전략형의 비교 정렬을 실제 결과에서 구분할 수 있어야 한다.
보조색·효과를 추가하기 전에 가장 중요한 정보가 무엇인지 다시 확인한다.

## 같은 내용을 다른 양식으로 만들 때

인원·기간·예산·출처·제약은 하나의 기준 자료에서 가져온다. 바꾸는 것은 제목의 초점,
대표 비주얼, 정보 배치와 전개 순서다. 한 방향을 장표마다 번갈아 적용하지 않는다.

- editorial: 경험을 보여주는 사진, 짧은 선언, 넓은 여백, 중요한 수치 한 가지를 크게.
- product: 사용물을 크게 보여준 뒤 구성품·사용 순서·작성 예시를 설명. 밝고 어두운 장표로 역할을 구분.
- strategy: 같은 기준의 비교, 자원과 일정의 연결, 보류 조건과 승인 요청을 명료하게.

씨앗도서관 사례에서 사용한 종이색·주황, 네이비·라임은 응용 사례다. 주제나 브랜드가 달라지면 바꾼다.
좋았던 결과의 색·14장 분량·특정 물건을 기본값으로 고정하지 않는다.
