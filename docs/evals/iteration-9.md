# 평가 9회차: 지난달 보고서 갱신 (2026-10-13)

`vars:`(숫자를 데이터에 연결)와 기간 단어(`latest`, `prev`)를 넣은 뒤, 지난달(9월) 월간 보고 폴더에 10월 데이터를
추가하고 "10월 데이터로 갱신해 줘"라고 요청했다. 10월은 매출이 감소로 돌아서고 목표를 넘은 팀이 없어지도록
만들어서, 숫자만 바꾸면 틀린 문장("영남팀만 목표를 넘었고", "-1.1% 늘어", "호남팀 달성률이 가장 낮아")이 남는다.
기준선은 pptx와 CSV만 받아 직접 수정했다.

| 실행 | 통과 | 토큰 | 도구 호출 | 시간 |
|---|---|---|---|---|
| 스킬 사용 1차 | 8/8 | 82,127 | 10 | 104s |
| 스킬 사용 2차(1차 결함 수정 후) | 8/8 | 82,205 | 9 | 92s |
| 기준선 | 8/8 | 105,986 | 16 | 198s |

스킬 쪽은 다시 빌드만으로 숫자·차트·워터폴이 10월로 바뀌고, 남은 일은 VARS가 알려 준 문장을 고치는 것이다.
기준선보다 토큰 22%, 시간 54% 적다. 처음 채점에서 양쪽 모두 "9월 수치 170.5가 남음"으로 1건씩 실패했지만,
추이 표의 9월 행이었으므로 채점기를 고쳤다(표 셀 제외).

## 실행 중 나온 개선점과 조치

| 개선점 | 조치 |
|---|---|
| 숫자 뒤 조사가 틀림("166.3억 원를") | `$rev를` → 값의 받침에 맞춰 을/를, 이/가, 은/는, 과/와, (으)로 자동 선택 |
| 감소 문장에 "-2.5%"가 들어가 이중 부정 | `$mom.abs`로 부호 없이 |
| 숫자 없는 서술이 갱신 대상에서 빠짐 | 값이 바뀐 빌드에서 `$var` 없는 문장을 장표별로 출력(제목·시사점·다음 단계 일정) |
| 다시 빌드하면 지난달 덱이 사라짐 | 기간이 바뀌면 `deck.2026-09.pptx`로 보관 |
| `diff: true` 같은 잘못된 키가 조용히 무시되고 %에 "억 원"이 붙음 | 모르는 키·형식 오류는 바로 안내, %에는 단위를 붙이지 않음 |
| 기간이 바뀌어도 표지 날짜가 그대로 | `date:`가 지난 빌드 그대로이면 알림 |
