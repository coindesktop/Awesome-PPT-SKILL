# 평가 7회차: 실적 보고 시각화 (2026-10-12)

보고서 시각화 4종(waterfall, donut, progress, status-table), 구성안 `report/performance`·`report/project`,
`pivot --bridge`를 넣은 뒤 새 평가 8(3분기 목표 대비 실적 보고)을 스킬 사용과 기준선으로 돌렸다. 6회차에서
확인하지 못한 평가 2(질문 5개 제한)도 다시 돌렸다.

| 평가 | 통과 | 토큰 | 시간 |
|---|---|---|---|
| 8 실적 보고, 스킬 사용 | 8/9 | 100,465 | 184s |
| 8 실적 보고, 기준선 | 8/9 | 88,680 | 184s |
| 2 공공 페르소나, 스킬 사용(재실행) | 6/7 (실질 7/7) | 85,353 | 123s |

- 평가 8 스킬 사용: 새 구성안을 추천해 고르고 진척 막대·워터폴(285.6→319.3억)·도넛·상태표를 모두 썼다.
  실패 1건은 전체 달성률을 `pivot --per`의 소수 둘째 자리 출력 때문에 101%로 적은 것이다.
- 평가 8 기준선: 달성률 100.7%는 맞췄지만 증감을 지역 요인으로 분해하지 못했다(지역별 묶은 막대 + 순위 목록).
- 토큰은 이번 평가에서 스킬 쪽이 13% 많았다. 장수(9장 대 7장), 톤 시안 단계, 첫 사용자 프로필 저장이 더해진
  탓이다. 시간은 같았다.
- 평가 2: 첫 질문 4개로 5개 제한을 지켰다. 색상 기준 실패는 이번 회차에 평가 1을 돌리지 않아 비교 대상이 없던
  탓이며, 6회차 평가 1 색(1F5EDC)과 비교하면 통과한다(2E75B6).

## 실행 중 나온 결함과 조치

| 결함 | 조치 |
|---|---|
| `pivot --help`가 도움말의 `%` 때문에 멈춤 | `%%`로 고침 |
| `--per` 비율이 1.01로 나와 100.7%를 못 구함 | 1 근처 비율은 소수 셋째 자리, `--per target --percent`로 달성률 % 안내 |
| 열 방향 증감인데 "vs previous row" 표기 | 비교 방향(row/column)을 표기 |
| 두 시점만 고르면 1년 변화에 CAGR 이름이 붙음 | 두 시점은 "증감률 A→B"로 표기 |
| chart-table이 지역 10개 중 6개만 표에 넣음, 증감률 열 없음, 정수 반올림 | 꼬리 6행 규칙은 시간 축에만, 기간 계열의 처음→끝 증감률 열, 1천 미만은 소수 첫째 자리 |
| 범주 축이 가나다순으로 정렬됨 | 파일 순서 유지, `top: N`은 큰 순 |
| 묶은 막대 20개에 라벨이 겹침 | 막대 폭보다 넓은 라벨은 생략(표가 수치를 보여 줌), 이전 기간은 회색·최신은 강조색 |
| progress가 99.5%를 "100% 근접"으로 표시 | 반올림하면 상태가 바뀌는 값은 소수 첫째 자리 |
| progress 10개 + 콜아웃이 넘침 | 콜아웃 높이를 먼저 확보하고 행 높이를 줄임 |
| `--bridge`가 상위 몇 개의 합계 비중을 알려 주지 않음 | 누적 비중(cumulative) 출력 |
| 표지의 "(가정)" 표기를 지어낸 수치로 경고 | 표지는 제외, 숫자 옆의 (예시)/(가정)만 경고 |
