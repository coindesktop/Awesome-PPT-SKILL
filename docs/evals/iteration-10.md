# 평가 10회차: 매달 쓸 보고서 틀 (2026-10-13)

판단 문장도 데이터에 연결하는 기능(`by:` + `pick: min`/`count:`, `$x.dir` 증가/감소)을 넣은 뒤, "매달 쓸 월간 보고
틀을 만들어 줘, 다음 달부터는 CSV만 추가해서 갱신할 거야"라고 요청했다. 채점기는 에이전트가 만든 deck.md를 손대지
않은 채 10월 데이터(매출 감소, 목표 달성 팀 없음)로 다시 빌드하고 결과를 검사한다.

| 실행 | 통과 | 토큰 | 도구 호출 | 시간 |
|---|---|---|---|---|
| 스킬 사용 | 8/8 | 96,055 | 21 | 172s |

- 에이전트는 `report/performance` 구성안으로 9장을 만들고, 숫자와 판단("최저 팀", "미달 팀")을 모두 `vars`로 연결했다.
- 손대지 않은 10월 재빌드에서 166.3억 원, 감소 서술이 맞게 나왔고 9월 수치·증가 서술은 남지 않았다.
- 기준선은 돌리지 않았다. 스킬 없이 "다음 달에 데이터만 넣으면 갱신되는 틀"을 만들 방법이 없기 때문이다.

## 실행 중 나온 개선점과 조치

| 개선점 | 조치 |
|---|---|
| 백업과 변경 알림이 숨김 파일 `.deck.vars.json`에만 의존: 파일 없이 폴더를 옮기면 지난달 덱이 말없이 덮어써짐 | 빌드할 때 숫자를 .pptx 안(사용자 지정 문서 속성)에도 저장하고, 숨김 파일이 없으면 이전 덱에서 읽음. 기간 기록이 아예 없는 덱도 `deck.prev.pptx`로 보관 |
| 12개월 데이터에서 `latest-11`을 "전년 동월"로 오기 | 문서에 `latest-12`는 13개월이 필요하고 12개월이면 시작 월을 라벨 변수로 쓰라고 명시 |
| 도넛 가운데가 "170"(제목은 170.5억 원) | 값에 소수가 있으면 가운데도 소수 첫째 자리 |
| 45자 제한이 갱신 후 숫자가 길어지며 걸림 | 갱신 빌드의 WARN으로 드러나므로 그대로 둠(문장을 줄이면 됨) |
