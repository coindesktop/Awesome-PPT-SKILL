# 평가 3회차 (2026-10-03) · MVP 판정

실행: 평가 5개 × 스킬 사용 1회(2회차 결함 수정 후). 기준선은 2회차와 같은 값을 쓴다.

| 평가 | 통과(사용) | 통과(미사용) | 토큰(사용) | 토큰(미사용) | 시간(사용) | 시간(미사용) |
|---|---|---|---|---|---|---|
| 1 첫 사용·본부장 보고 | 7/7 | 6/7 | 77,149 | 108,663 | 100s | 235s |
| 2 같은 데이터·공공 페르소나 | 7/7 | 7/7 | 79,375 | 91,818 | 110s | 201s |
| 3 기존 덱 부분 수정 | 7/7 | 7/7 | 71,543 | 72,154 | 64s | 69s |
| 4 템플릿 없음·친근한 소개 | 6/6 | 6/6 | 76,262 | 112,568 | 96s | 287s |
| 5 통계 키 없음 | 4/4 | 3/4 | 78,341 | 127,284 | 69s | 259s |
| 합계 | 31/31 | 29/31 | 382,670 | 512,487 | 440s | 1,051s |

토큰 -25%, 시간 -58%. 2회차에서 기준선보다 많았던 평가 3도 기준선 이하로 내려왔다(도구 호출 12회 → 9회).
서브에이전트 고정 오버헤드(약 6만 토큰)를 빼면 덱 작업 자체의 절감률은 약 70%다.

## MVP 기준

| 기준 | 결과 |
|---|---|
| 모든 평가 기준 통과 | 31/31 |
| 기준선보다 적은 토큰 | 5개 평가 모두 이하, 합계 -25% |
| 치명 결함 0건 | 수치 날조 0, 범위 밖 장 변경 0, qa 실패 0 |
| 육안 품질 기준선 이상 | 네이티브 차트·표, 디자인 일관성, 페르소나별 톤(executive·public·forest)이 기준선보다 나음 |

## 3회차에서 나온 결함과 조치

| 결함 | 조치 |
|---|---|
| 개조식 lint가 '검토 필요'를 ~요로 오탐 | 동사 어미(~어요·~해요 등)만 검사 |
| 합산 비중(서울+경기)을 구할 수 없음 | `pivot --group 수도권=서울,경기 --where col=v` |
| CAGR이 연도가 행일 때만 나옴 | 연도가 열이면 행마다 CAGR(합계 포함) |
| `growth: true`가 chart-takeaway로 추론되어 무시됨 | growth가 있으면 chart-table로 추론 |
| KPI 값('월 49만 원')이 타일 안에서 줄바꿈 | 값이 한 줄에 들어가도록 글자 축소 |
| 제목이 두 줄로 넘어가도 경고 없음 | 제목 길이 WARN |
| World Bank 대체 링크가 KOR→KO로 잘림, CSV 버튼은 ZIP | ISO3→ISO2 매핑, `pptkit data`가 ZIP을 읽음 |
| chart 연산이 과거 값 변경을 알리지 않음 | "existing points changed: 2025Q3 489→499" 출력 |
| map이 범위 밖 장의 sparse를 반복, 슬라이드 크기 미표시 | map에서 sparse 제외, 머리줄에 크기 표시 |
| stack이 첫 박스 폭에 고정 | `width: max` |
